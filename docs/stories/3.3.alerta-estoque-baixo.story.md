## Story

**As a** dono do salão,
**I want** ver de forma clara, na própria tela de produtos, quais itens estão com estoque abaixo do mínimo configurado,
**so that** eu saiba o que repor sem precisar comparar número por número manualmente.

## Acceptance Criteria

1. Na tela `/produtos`, cada produto **ativo** com `estoqueAtual < estoqueMinimo` exibe um indicador visual de alerta (badge "Estoque baixo") na linha da listagem — reaproveita a classe `.badge` já existente (Story 4.1/4.2), sem CSS novo além de uma variante de cor.
2. A tela ganha um filtro de abas (mesmo padrão visual de `/agendamentos`: "Próximos"/"Passados"/"Todos") com duas opções: "Todos" (padrão, comportamento atual) e "Estoque baixo" (só produtos ativos com `estoqueAtual < estoqueMinimo`).
3. A condição de alerta é puramente `ativo && estoqueAtual < estoqueMinimo` — nenhum tratamento especial pra `estoqueMinimo = 0` é necessário: matematicamente um produto com mínimo 0 só entra em alerta se o estoque atual for negativo, o que já é um sinal válido (a Story 3.2 decidiu permitir estoque negativo em vez de bloquear saídas).
4. Produto inativo nunca entra no alerta nem no filtro "Estoque baixo", mesmo que `estoqueAtual < estoqueMinimo` numericamente (mesma lógica de "só o que está ativo importa" já usada em outras listagens do projeto).
5. Nenhuma mudança de comportamento em `/produtos/[id]` nem nas actions de cadastro/movimentação — esta story é só uma camada de leitura/apresentação sobre dados que já existem desde as Stories 3.1/3.2.
6. Nenhuma regressão; `npm run test`, `npm run lint` e `npm run build` continuam verdes.

### Contexto

- `src/app/(app)/produtos/ProdutoRow.tsx` já exibe `estoqueAtual`/`estoqueMinimo` como números simples e um badge de situação (Ativo/Inativo, reaproveitando `.badge.CONCLUIDO`/`.badge.off`). - `src/app/(app)/agendamentos/page.tsx` já tem o padrão de abas de filtro por query param (`filtro=proximos|passados|todos`), renderizado como links `<a href="...">` com classe `btn`/`btn ghost` conforme ativo. Reaproveitar o mesmo padrão de markup pra `/produtos`. `[Source: src/app/(app)/agendamentos/page.tsx]`
- Prisma/SQLite não permite comparar duas colunas da mesma linha (`estoqueAtual < estoqueMinimo`) diretamente numa cláusula `where` sem SQL raw — a solução mais simples e proporcional ao volume de dados (produtos de um salão, não um catálogo grande) é buscar os produtos normalmente e filtrar em memória com a função pura `emAlerta`.
- Nenhum model novo, nenhuma migração — esta story só lê `Produto.estoqueAtual`/`estoqueMinimo`/`ativo`, todos já existentes desde a Story 3.1.
