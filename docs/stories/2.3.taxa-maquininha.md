## Story

**As a** dono do salão,
**I want** registrar a taxa que a maquininha cobra por forma de pagamento,
**so that** o caixa mostre quanto de fato entrou na conta, não o valor bruto.

## Acceptance Criteria

1. Nova entidade `TaxaPagamento` (`formaPagamento @unique`, `percentual Float @default(0)`, `valorFixo Float @default(0)`, `ativo Boolean @default(true)`, `criadoEm`). A migração é aditiva (tabela nova); nenhum dado existente é tocado.
2. Existe a tela `/taxas` (**acesso só DONO** — `exigirPapel("DONO")`) para ver e editar as 4 taxas (uma linha por forma: DINHEIRO, PIX, DEBITO, CREDITO), com percentual e valor fixo por transação. DINHEIRO e PIX começam em 0.
3. `src/lib/financeiro.ts` ganha função **pura** `taxaDePagamento(valor, taxa)` e `resumoCaixaComTaxas(pagamentos, qtdAtendimentos, taxasPorForma)`, sem I/O, cobertas por testes (taxa 0; só percentual; só valor fixo; percentual + fixo; valor fixo maior que o pagamento → taxa limitada ao valor).
4. `/caixa` passa a exibir, por forma de pagamento: **bruto**, **taxa**, **líquido**; e o **total de taxas do dia** e o **total líquido do dia**. O total geral bruto continua aparecendo.
5. `FechamentoCaixa` ganha `totalTaxas Float @default(0)` e `totalLiquido Float @default(0)`; `fecharCaixa` recalcula e persiste esses valores no servidor. Migração aditiva (default 0 preserva fechamentos antigos).
6. **Sem regressão:** `resumoCaixa` (usado no painel e como base de comissão) **não muda** — a comissão continua sobre o bruto nesta story (o toggle bruto/líquido é a Story 2.5). Painel do dia e relatório de comissões continuam idênticos.
7. `npm run test`, `npm run lint`, `npm run build` verdes. Seed atualizado com as 4 taxas (DINHEIRO/PIX 0; DEBITO e CREDITO com exemplos, ex.: 1,5% e 3,5%).

## Dev Notes

### Contexto (Stories 1.2, 1.7, 2.2)

- `src/lib/financeiro.ts`: `reais(n)` (half-up), `FORMAS_PAGAMENTO`, `FormaPagamento`, `resumoCaixa(pagamentos, qtd)` → `{ porForma, totalGeral, ticketMedio }`. **Não mexer** nas existentes.
- `src/lib/sessao.ts` (Story 2.2): `exigirPapel("DONO")` para guarda de rota; nas actions, `const { papel } = await exigirSessao(); if (papel !== PAPEL_DONO) return { ok:false, erro: ERRO_SEM_PERMISSAO }`.
- `src/app/(app)/caixa/page.tsx` já usa `resumoCaixa` e mapeia `porForma` → colunas `totalDinheiro/Pix/Debito/Credito`. `FecharCaixa.tsx` é o client component com "Fechar caixa" / "Reabrir".
- `src/app/(app)/caixa/actions.ts` `fecharCaixa` já recalcula no servidor via `resumoCaixa` e grava o `FechamentoCaixa` numa transação.
- `Nav.tsx` (Story 2.2) tem o array `links` com flag `dono: boolean`.
- Seed guardado (`--force`); ordem de `deleteMany` importa por FKs (`TaxaPagamento` não tem FK, mas manter no bloco de limpeza).

### Decisões a tomar (registrar no Change Log)

1. **Taxas em produção:** a migração cria a tabela vazia. As 4 taxas precisam existir para o caixa não quebrar. Opções: (a) `page.tsx`/`caixa` tratam forma sem registro como taxa 0 (defensivo — recomendado); (b) um passo de seed no start do Railway. Recomendação: **(a)** — `taxasPorForma[forma] ?? { percentual: 0, valorFixo: 0 }`; a tela `/taxas` cria via `upsert` quando o dono salva. Sem passo extra no deploy.
2. **`taxaDePagamento` — limite:** se `valorFixo` (ou %+fixo) exceder o valor do pagamento, a taxa é limitada ao valor (líquido nunca negativo). Confirmar essa regra com o @qa.
3. **`ticketMedio`:** permanece sobre o bruto (receita cobrada por atendimento). O líquido é uma linha à parte. Se o dono preferir ticket líquido, é decisão de produto para outra story.

### Assunções explícitas

- Uma taxa por forma de pagamento (escopo geral), igual para toda maquininha. Múltiplas maquininhas / bandeiras / parcelamento = fora de escopo.
- Taxa é aplicada **por pagamento** (não por atendimento) e some no fechamento; não altera o `Pagamento.valor` gravado (que continua sendo o bruto recebido do cliente).
- Trocar uma taxa afeta só cálculos futuros; fechamentos já persistidos guardam o valor da época (`totalTaxas`/`totalLiquido` na linha do `FechamentoCaixa`).

### Edge cases

- Forma de pagamento sem `TaxaPagamento` → taxa 0 (defensivo).
- `percentual` fora de 0..100 ou `valorFixo` negativo → erro pt-BR, não grava.
- Dia sem pagamentos → total de taxas 0, total líquido 0.
- Caixa já fechado antes desta story → `totalTaxas`/`totalLiquido` = 0 (default); a UI mostra 0 e um aviso "fechado antes do controle de taxas" é opcional.

### Testing

- **Unit:** ver Task 3.
- **Manual:**
  1. `/taxas` (como dono): definir DEBITO 1,5% e CREDITO 3,5% + R$ 0,10 fixo.
  2. Concluir um atendimento de R$ 100 pago no crédito → `/caixa` mostra bruto 100, taxa 3,60, líquido 96,40.
  3. Total de taxas e total líquido do dia batem com a soma das linhas.
  4. Fechar o caixa → reabrir → conferir no Studio `totalTaxas`/`totalLiquido` gravados.
  5. `/painel` e `/comissoes` inalterados (comissão ainda sobre o bruto).
  6. `/taxas` como balcão → redireciona.
