## Story

**As a** desenvolvedor,
**I want** as novas entidades e campos no schema Prisma com migração não destrutiva,
**so that** as demais stories tenham base para gravar pagamentos, comissões e fechamentos.

## Acceptance Criteria

1. `schema.prisma` inclui `Pagamento` (id, agendamentoId, valor, formaPagamento, dataHora, conferido default false, criadoEm) com `onDelete: Cascade` na relação com `Agendamento`.
2. `schema.prisma` inclui `ComissaoRegra` (id, profissionalId `@unique`, percentual, criadoEm) com `onDelete: Cascade`, e `FechamentoCaixa` (id, data `@unique`, totalDinheiro, totalPix, totalDebito, totalCredito, totalGeral, qtdAtendimentos, ticketMedio, observacoes?, criadoEm).
3. `Agendamento` ganha `valorCobrado Float?`; o comentário de status passa a listar `AGENDADO | CONCLUIDO | CANCELADO | FALTOU`.
4. `Profissional` ganha `comissaoPercentual Float @default(0)` e relação opcional `comissaoRegra`.
5. A migração aplica sobre um banco com dados existentes sem apagar agendamentos, serviços, profissionais ou clientes (todos os campos novos são `?` ou `@default`).
6. `npm run db:seed` popula ao menos 2 `ComissaoRegra` e alguns `Pagamento` de exemplo consistentes com agendamentos `CONCLUIDO` (com `valorCobrado` preenchido).
7. `prisma/migrations/` passa a existir com a migração `epic1_financeiro`; `package.json` ganha `"db:migrate": "prisma migrate dev"`.
8. `npm run build` (roda `prisma generate` + `next build`) e o typecheck passam.

## Dev Notes

### Contexto de arquitetura (fonte: `docs/architecture.md` §2)

DDL alvo (não copiar cega — conferir nomes com o schema atual):

```prisma
model Pagamento {
  id             String   @id @default(cuid())
  agendamento    Agendamento @relation(fields: [agendamentoId], references: [id], onDelete: Cascade)
  agendamentoId  String
  valor          Float
  formaPagamento String   // DINHEIRO | PIX | DEBITO | CREDITO
  dataHora       DateTime @default(now())
  conferido      Boolean  @default(false)
  criadoEm       DateTime @default(now())
  @@index([dataHora])
  @@index([agendamentoId])
}

model ComissaoRegra {
  id             String   @id @default(cuid())
  profissional   Profissional @relation(fields: [profissionalId], references: [id], onDelete: Cascade)
  profissionalId String   @unique
  percentual     Float
  criadoEm       DateTime @default(now())
}

model FechamentoCaixa {
  id              String   @id @default(cuid())
  data            DateTime @unique
  totalDinheiro   Float
  totalPix        Float
  totalDebito     Float
  totalCredito    Float
  totalGeral      Float
  qtdAtendimentos Int
  ticketMedio     Float
  observacoes     String?
  criadoEm        DateTime @default(now())
}
```

### Decisões relevantes

- **Manter `ComissaoRegra` E `Profissional.comissaoPercentual`** (espelho denormalizado). A regra é
  canônica; o campo no profissional é para exibição rápida na lista e é atualizado pela mesma action
  na Story 1.3. (Arquitetura §2.1). Se o time decidir simplificar e remover `ComissaoRegra`, registrar
  aqui no Change Log — mas a recomendação é manter, para não pagar migração na fase 2.
- **Status permanece `String`** — não criar enum Prisma (evita migração de tipo). Os literais serão
  centralizados em `src/lib/financeiro.ts` na Story 1.2.
- **`prisma migrate dev`**: o projeto hoje só usa `db:push`. Esta story faz a transição uma vez.
  `db:reset` e `db:seed` continuam válidos; `db:push` pode continuar existindo para hotfix local.
