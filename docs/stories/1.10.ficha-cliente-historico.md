## Story

**As a** operador do balcão,
**I want** abrir a ficha de um cliente e ver seu histórico,
**so that** eu conheça o cliente e saiba quando foi a última visita.

## Acceptance Criteria

1. A lista de clientes (`/clientes`) permite busca por nome ou telefone (query param `?q=`) e cada cliente abre a ficha em `/clientes/[id]`.
2. A ficha mostra contato (telefone, email), observações editáveis e a data da última visita concluída (`Agendamento` `CONCLUIDO` mais recente por `inicio`).
3. O histórico lista os agendamentos do cliente (data, serviço, profissional, valor cobrado, status), mais recentes primeiro.
4. A ficha tem atalho para criar novo agendamento já com o cliente selecionado.
5. Cliente sem histórico mostra "Nenhum atendimento registrado" e última visita "—".

## Dev Notes

### Contexto (fonte: `docs/architecture.md#5`; código atual)

- `src/app/clientes/page.tsx` (lista) e `ClienteRow.tsx` (edição inline) já existem. `Cliente` já tem
  `observacoes String?`. `Agendamento` tem relação `cliente`.
- SQLite + Prisma: `contains` é case-insensitive por padrão no SQLite para ASCII; `mode: "insensitive"`
  **não** é suportado no conector SQLite — não usar. Aceitável para o MVP.
- `src/lib/format.ts`: `dataHora`, `brl`, `STATUS_LABEL` (com `FALTOU` após Story 1.5).
- `NovoAgendamento.tsx` recebe listas de clientes/serviços/profissionais e usa `criarAgendamento`.
  A pré-seleção via query param é a mesma necessidade da Story 1.6 (Task 4) — coordenar para não duplicar.

### Assunções explícitas

- Busca simples por substring; sem paginação (salão pequeno, poucos clientes).
- "Última visita" considera só `CONCLUIDO` (não `AGENDADO` futuro nem `FALTOU`).
- Histórico mostra todos os status (inclusive cancelado/faltou) para o operador ter contexto.

### Edge cases

- `q` vazio ou só espaços → listar todos.
- `/clientes/[id]` com id inválido → `notFound()` (página 404 padrão do Next).
- `valorCobrado` null (agendamento não concluído) → exibir "—".

### Testing

- **Sem teste automatizado** (CRUD/consulta simples).
- **Manual:**
  1. `/clientes?q=maria` → filtra; clicar abre `/clientes/[id]`.
  2. Ficha da Maria (seed): mostra histórico com o corte; se concluído, última visita preenchida.
  3. Editar observações → persiste após reload.
  4. "Novo agendamento" a partir da ficha → form abre com Maria selecionada.
  5. Cliente novo sem agendamento → "Nenhum atendimento registrado", última visita "—".
