## Story

**As a** operador do balcão,
**I want** remarcar um atendimento ou marcá-lo como falta/cancelado,
**so that** a agenda reflita o que realmente aconteceu.

## Acceptance Criteria

1. Um agendamento `AGENDADO` permite alterar início e/ou profissional; o fim é recalculado a partir de `servico.duracaoMin`.
2. A remarcação reaplica a checagem de conflito de horário do profissional existente; conflito bloqueia com mensagem em pt-BR.
3. Ações "Cancelar" e "Faltou" mudam o status para `CANCELADO` / `FALTOU` e pedem confirmação antes de aplicar.
4. Agendamentos `CANCELADO` e `FALTOU` não entram em nenhum cálculo de caixa, comissão ou painel (garantido pelos filtros de query dessas stories).
5. O `STATUS_LABEL` e a exibição na agenda cobrem os quatro status (Agendado, Concluído, Cancelado, Faltou).
6. Só agendamentos `AGENDADO` podem ser remarcados; `CONCLUIDO` não.

## Dev Notes

### Contexto (fonte: `docs/architecture.md#4`, `#5`; código atual)

- `src/app/agendamentos/actions.ts` já tem a checagem de conflito em `criarAgendamento` (linhas ~32-42):
  ```ts
  const conflito = await prisma.agendamento.findFirst({
    where: { profissionalId, status: { not: "CANCELADO" }, inicio: { lt: fim }, fim: { gt: inicio } },
  });
  ```
  Ao remarcar, é preciso **ignorar o próprio registro** e também excluir `FALTOU` do conflito.
- `mudarStatus` hoje valida `["AGENDADO", "CONCLUIDO", "CANCELADO"]` — adicionar `FALTOU`.
- `src/components/DeleteButton.tsx` é o padrão atual de ação destrutiva com confirmação.
- `STATUS_LABEL` em `src/lib/format.ts` hoje não tem `FALTOU`.

### Assunções explícitas

- Remarcar não altera cliente nem serviço (só horário e profissional). Trocar serviço = cancelar e criar novo.
- `FALTOU` é distinto de `CANCELADO` para efeito de histórico/relatório futuro, mas ambos são ignorados nos cálculos financeiros do MVP.

### Edge cases

- Remarcar para o mesmo horário/profissional (sem mudança real) → permitido (no-op efetivo), sem erro.
- Novo horário conflita só com um `CANCELADO`/`FALTOU` → permitido.

### Testing

- **Sem teste automatizado** (regra de conflito é de query; validar manual).
- **Manual:**
  1. Remarcar o agendamento de hoje para +1h → ok, fim recalculado.
  2. Remarcar para um horário que colide com outro AGENDADO do mesmo profissional → erro pt-BR.
  3. Remarcar mantendo o mesmo horário → não acusa conflito consigo mesmo.
  4. Marcar "Faltou" → status FALTOU, pede confirmação; agenda mostra "Faltou".
  5. Tentar remarcar um CONCLUIDO → bloqueado.
